# introduction

> AI security is not like normal cyber security.

- In normal security, a known flaw usually has a fix (a patch).
- AI attacks like prompt injection and jailbreaking have no single fix.
- This is because AI does not always give the same answer twice.

> The good news

- You can't make an AI fully safe from these attacks. But you can make them much less likely. This room shows you how.

> What you will learn

- Why AI security is about chances, not guarantees. No one defence can stop every attack.
- System prompt hardening. Writing stronger instructions for the AI helps, but it has limits.
- Input and output guardrails. These are filters that check what goes into and comes out of the AI. They help, but they can fail and have trade-offs.
- Deployment controls and least privilege. Giving the AI only the access it needs means less damage if an attack works.
- Defence-in-depth. Using many layers of protection together is the only realistic approach.
